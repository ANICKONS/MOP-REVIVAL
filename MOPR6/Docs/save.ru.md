# Граница сохранения

## Что делает

- Ядро: машина состояний барьера `Core/src/Save/SaveBarrier.cs` (время — снаружи): `Live` → поднят → записан /
  отменён; срок отмены — 1,5 с без записи, после записи в той же сцене системы возобновляются через 3 с.
- Игра: `Mod/Save/SaveHooks.cs` получает каждое состояние FSM через единственный префикс MOPR6 на
  `FsmState.OnEnter` (`Engine/FsmHooks.cs`), классифицирует его один раз (кеш):
  - «Mute audio» кнопки точки сохранения (первое состояние после щелчка, до её `SaveString`/`SetIsKinematic`) —
    поднять барьер;
  - любое состояние с `SendEvent BroadcastAll SAVEGAME` (точки сохранения, смерть, телефон) — поднять, если ещё
    не поднят, и отметить запись.
- Префикс срабатывает до действий состояния, поэтому барьер поднят раньше первого `Save*` игры. Подъём: все
  системы приостанавливаются, журнал возвращает всё и замораживается; что не вернулось — пишется в лог по имени
  (Т6.2). «Сохранить и выйти» заканчивается вместе со сценой; новая сцена начинается без барьера.

## Что доказано

Барьер не зависит от того, какие системы что делают: он сам возвращает журнал. Пока системы этапа 1 журнал не
используют (они ничего не меняют в сцене), проверка идёт тестовой системой-зондом.

## Что проверено

- Модульные тесты `SaveBarrierTests`: сохранить и выйти, отмена — возобновление ≤ 2 с, «ничего не записано» =
  отмена, сохранение без выхода.
- `quick1` (2026-10-29): зонд скрыл гостиную (76 рендереров), `mopr restore` — «restored 76, not restored 0»,
  журнал пуст; снова скрыл, сохранение через `SAVEGAME` — барьер поднят 1 раз (`…/SAVEGAME#Button/Mute audio`),
  не вернулось 0, ошибок нет.
- `eq-save-load` в `full` с включёнными системами — 0 необъяснённых, сейв совпадает с ванилью.

Не проверено в игре: отмена сохранения с системой, которая держит изменения (возврат ≤ 2 с), — появится вместе с
первой системой, которая держит изменения (этап 2).
